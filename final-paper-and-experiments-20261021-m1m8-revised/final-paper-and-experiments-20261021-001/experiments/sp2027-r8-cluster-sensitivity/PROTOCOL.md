# Frozen R8 cluster-weight sensitivity plan

Scope: post hoc sensitivity on the complete saved `sp2027-r7-crossfit/predictions.json` OOF records. No LLM requests, retraining, calibration, threshold changes, new data or alteration of old files. Freeze this plan, analysis.py, verify.py and exact input SHA256 in freeze.json before analysis execution. `detailed_results.json` is read only for the original suite-max BA comparison.

Cells fixed in advance: baseline/rules × undefended/jointbucket1024/jointconstant × cancel/return. Use all saved 11 attackers and their stored binary `pred`, including majority. Do not threshold mean scores or pick a new operating threshold. Retain every episode and all mixed-label customers.

Metric 1: original episode-weight BA = one half of pooled positive-episode sensitivity plus pooled negative-episode specificity. For each attacker separately, metric 2 is class-conditional customer-equal BA: compute mean correctness within each (customer, true class) stratum, average those customer means within class, then average the two class rates. Thus every customer present in a given class has the same total weight in that class. A mixed-label customer participates in both class averages, with its positive and negative episodes separated; do not assign a single customer intent. Suite maxima are reselected independently for each metric, not necessarily the same winning attacker. Save all per-attacker BAs and all per-customer/class counts and correctness means.

Leave-one-positive-customer-out: enumerate every customer with at least one positive episode within the cell. Remove that customer's entire set of episodes (including its negative episodes), without retraining any fold model. Recompute both metrics for every attacker and suite maxima; preserve deletion ID, remaining episode/class/customer counts, positive/negative/mixed customer counts, winners, per-attacker values and min/max over valid deletions. A deletion with either class absent is explicitly invalid, never assigned BA=.5. These are deterministic influence ranges, not confidence intervals or prospective heldout tests. Report parent-cell denominators plus valid/invalid deletion counts.

No single per-customer mean-score classifier: targets vary across a customer's tasks. Combining scores then forcing one ground-truth label would change the estimand or discard mixed customers; the first two analyses answer the requested weighting/influence question without this ambiguity.

Statistical scope: scores and binary predictions remain conditional on the previously fitted OOF fold attacks, training/calibration and known cohort. Customer weighting and deletion expose dependence on customer/task composition; they do not include retraining uncertainty, supply independent customers, repair original prior access to public tasks, or create confirmatory evidence. No significance threshold, hypothesis choice or tuning will depend on computed sensitivity outputs. Only point sensitivity is planned; no added bootstrap/power claims.

Verification: a separate standard-library verifier checks input and frozen code hashes, unique episode grid, folds per customer, saved binary predictions, all numerical results by an alternate direct-weight formulation, original suite-max BA agreement, deletion membership/counts and result hash. It writes only verification.json in this new directory. No package dependencies beyond Python standard library.
