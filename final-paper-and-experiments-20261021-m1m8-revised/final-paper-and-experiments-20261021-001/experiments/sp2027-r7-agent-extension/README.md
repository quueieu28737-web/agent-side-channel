# R7 same-provider Luna Agent extension

The fixed 150-run collection uses gpt-6-luna/low for both planner and a separate user-simulator context through the authenticated Codex subscription app-server. Structured decisions are dispatched to the existing public retail sandbox; known-name errors and unknown-name rejections are retained. Requested and returned model identifiers and raw events are retained. No API key is used.

The 75 tasks are a convenience subset: the first 29 tasks in the inherited training list after excluding pilot IDs 0–4, plus all 46 inherited test tasks. They are not a random sample of new customers. There are 34 existing public customers: 10 training and 24 test, with no customer overlap. Two prompts and one repetition produce 58 training and 92 test trajectories. Each prompt-specific attacker has 29 training and 46 test examples. All 115 original tasks/53 customers were previously used in manuscript development. The 10-run feasibility pilot is separate and is never counted toward the formal 150.

The collection freeze is formal_plan.json. The appended D2/network algorithms and configuration were frozen at run 44/150 before any formal test output; calibration parameters are computed after all 150 collection using only 58 training trajectories. They were not frozen before Luna test collection. APPENDED_ANALYSIS_FREEZE.json and TIMING_AND_POWER.md retain this boundary. No old experiments, old protocol or original manifest are edited.

D2 dispatch ablations are all/read/write views with fixed logistic regression, inherited gradient boosting and majority control. The inherited gradient-boosting min_samples_leaf=20 prevents splitting with 29 samples; actual constant-output fractions are retained. Customer bootstrap suites reselect their maximum in every draw. Intervals are descriptive conditional on fixed fitted predictions and do not include training uncertainty.

The separately appended network analysis uses training-only template/donor/cap calibration and actual local TLS 1.2 replay for raw, padding, shadow shaping and joint conditions, using the inherited fixed R4 attacker suite. It adds zero LLM requests. This is a local agent-tool replay link, not model-provider transport, live Agent replanning or a complete replication of original E12. There is no cross-provider or independent human audit claim.

Public release uses raw-evidence-public.zip, documented user-home path redaction, and per-file original/public SHA256. Original scientific outputs remain untouched locally. Credentials and residual absolute user paths cause packaging to fail closed. No environment is packaged. See PORTABILITY_NOTES.md and requirements-public.txt for no-LLM recomputation from the public ZIP, including native rewards and optional full network analysis. Final completed scale is recorded in formal_collection.json; validation in formal_validation.json/public_validation.json/public_network_validation.json; compact tables are generated only after completion from saved JSON.
The Luna reads-only ablation keeps only get_/find_/list_ dispatch names. It is not the complete no_writes complement used by Sol E12: think, calculate, handoff and unknown-tool names may fall outside both Luna read and write views. The compact report retains each view count and all excluded names/counts as reporting-only statistics. These two ablations must not be treated as equivalent across Sol/Luna.



Counter semantics are receipt-specific. The original frozen formal_summary.json/formal_validation.json and original public_validation.json retain legacy real_tool_calls meaning TOTAL dispatch attempts (1015 overall). The derived corrected receipts and compact_manifest.per_prompt instead use real_tool_calls for KNOWN-NAME dispatch attempts (1003 overall: baseline498/rules505), with total1015 and unknown12 separate. Neither counter means successful executions: known-name attempts include env.step/validation errors. Network call_ratio is the ratio of total test dispatch records (including errors, unknown requests and cover) to raw test records. Public ZIP validation uses ZIP model evidence plus the checkout's pinned public vendor/tasks/tool/helper sources and dependencies; the ZIP is not self-contained. The root dependency-closure receipt binds those benchmark inputs to the frozen R4 authority chain.

The benchmark dependency closure is recorded in provenance/r7-review/portable-verification/luna-dependency-closure.json and luna-dependency-receipt.json (relative to package root). The receipt reports PASS for the 24 public load_tau code/data files against both the frozen R4 runtime manifest and the prior publication manifest. compact_manifest.json records their SHA256 and checker location; public_zip_is_self_contained=false.
