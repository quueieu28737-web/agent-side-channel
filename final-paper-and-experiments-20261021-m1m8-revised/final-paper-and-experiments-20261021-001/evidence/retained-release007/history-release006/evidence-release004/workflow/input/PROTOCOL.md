## 1. Claim, hypothesis and scope

**Question:** under the same factual information and request/time limits, does a dependency-oriented implementation of the SCOPE receiver-contract procedure improve model-assisted finite release-contract judgments relative to a complete, active generic structured checklist?

The primary contrast is V minus T. H0 is a nonpositive mean effect; H1 is a positive mean effect on the fixed primary battery and assigned request slots. R is the complete flat checklist, a secondary comparator. Expected direction is a hypothesis, not an observed or guaranteed effect. This is not a demonstration that SCOPE invented the checks, beats every possible complete checklist, validates all five dimensions, helps human researchers, authenticates original-paper experiments, or establishes real-world privacy/defense efficacy.

The manipulated variable is the recommended reasoning organization. All arms get the same common checks, execution semantics, evidence, output schema and ability to perform any correct reasoning. R self-organizes; T extracts/checks/reconciles individual claims; V indexes receiving conditions and traverses/joins dependencies from final recipients. T may use graphs and joins: withholding that ability would weaken the control. V receives neither an extra oracle nor additional evidence. The method cards use neutral labels, without claims that one is superior.

See `OPERATIONAL-DELTA.md`. The distinctive operation is a procedural recommendation, not proof of a unique algorithm or a new information-theoretic rule. A correct unrestricted baseline can solve every case.

## 2. Source-grounded but controlled cases

Inputs are existing locally pinned public-artifact releases. No new source is downloaded, no source code from those projects is executed, and no old analysis is rerun.

The main manuscript is a read-only concurrent-edit watcher, not an input to this experiment. An initial offline audit stopped on its changed hash; the interruption is retained. Preparation neither overwrites nor rolls back that file. Actual source inputs, protected baseline sections and old experiment records retain strict hash checks. No live engineering gate has been relaxed.

- UI Traces: normalized archive release bound to the pinned raw archive, inventory, episode file and original ingestion freeze. One root is an exact question-hash group. Within a group select the first deterministic hash-ordered pair with different model IDs and different nonempty first-24 action-category prefixes. This selects distinguishable source pairs deliberately; it does not estimate the prevalence of naturally distinguishable executions.
- FP-Agent: author-released feature vectors, not raw browser trajectories. There are 7,719 rows but only 18 `source_file` groups. Select one different-behavioral-block pair per group. The grouping is a file/proxy group, not an authenticated visitor, person, host or independent mechanism.

Observed token equality/order is retained by a pair-specific bijection. UI auxiliary tokens encode episode event-count and prefix category-count values; FP auxiliary tokens encode the first 16 static-feature values. Actual source contents, labels, names, URLs and question text are not put in public question packets. Tokenization does not preserve feature distances or a published classifier's geometry. No model inference performance on those original features is reproduced.

**Constructed controls:** the processing DAG, recipients, masks, operation domains, missing settings and final-view equality claims are researcher-created. They are not discovered errors in source papers, observed deployed defenses, captured downstream regenerations, or new agent runs. The finite claim concerns exactly the supplied state pair and release function, not full-system noninterference. Equal views for this pair do not imply general protection; unequal views do not estimate a population leakage rate or prove private-task inference.

This narrow construct exercises receiver/channel/pipeline alignment and evidence closure. Attacker adaptation, private-goal inference, natural-paper synthesis and execution utility are not measured.

## 3. Frame, splits and independence

The checked frame has 789 eligible UI question groups. Hash ordering fixes 16 development groups and 512 primary groups, with the remaining 261 unused. The latter are **not a replacement pool**. All 18 eligible FP groups form a separate source-transfer set. The pack contains 546 roots and 1,638 query judgments; only the 512 primary roots enter the primary effect. Within-root query means are one bounded score, not three independent samples.

The two source repositories do not occur in the previous six-repository model comparison. This is repository-disjointness from that earlier battery, not six new independent families, an unseen-source claim for pretraining, semantic question-disjointness, or independent curator selection. Exact-hash grouping does not eliminate semantically similar tasks. The same graph semantics/templates occur across sources. FP is a limited source-transfer stress check, not a powered cross-domain semantic-generalization result.

The 16 development roots are withheld from the formal dispatch schedule. No development model call is authorized here. If future development calls prompt a material change to cards, scoring or cases, this version cannot become the same confirmatory study: create a separately versioned protocol before formal collection and disclose the changes. Do not turn old or new development answers into held-out observations.

## 4. Ground truth, grading and circularity controls

Every packet supplies a DAG with elementary list operations and two Boolean/binary configuration domains. For each query the oracle enumerates all four jointly admissible configurations, evaluates the two states at the named receiver and counts exact final-view equalities. All-equal is SUPPORTED; no-equal is REFUTED; mixed is INSUFFICIENT. An unrelated unknown does not force uncertainty, and an unaffected known counterexample can refute equality despite other unknowns.

The primary root score is the fraction of its three judgments with correct decision, exact equal/possible configuration counts and correct supplied source/query IDs. Every arm gets these requirements. No SCOPE wording, intermediate graph, condition tuple or free-text explanation is graded. Evidence IDs bind the state pair/query, not the completeness of a natural-language rationale. Thus this is joint decision/witness correctness, not independent semantic grading of explanations.

Python uses recursive memoized evaluation; JavaScript uses iterative dependency scheduling. The JavaScript checker computes from public packets before reading the reference table. Both were written by the same assistant: separate code paths, not independent researchers or independent test designers. Shared design mistakes remain possible. Synthetic unit/metamorphic tests cover ordering, irrelevant unknowns, bypasses, denied outputs and bad records. The algorithmic oracle can solve everything; constant and one-hop heuristics are diagnostic only, never substituted for the strong T comparator.

## 5. Assignment and identical access/budgets

Before any new model response, each nondevelopment root receives one request per R/T/V arm in an independent OS-entropy shuffle of its three slots. The complete saved schedule, not regeneration of randomness, is the replay record. Case order is fixed by the documented hash ordering. Each arm is a fresh session. Conditional on the R slot, T/V occupy a random pair of positions. No arm gets prior responses, aggregate scores or reference answers.

The same model (`gpt-6-luna`, low effort) is proposed, not invoked. All arms get identical semantic operations and common instructions. Card lengths are checked within 10%; actual input/output tokens are not claimed equal. Each combined input must be at most 32,768 UTF-8 bytes. Identical local wait/time thresholds do not certify equal actual compute. Record all acknowledged tokens and process/transport time, including failures.

## 6. Primary analysis and failure rules, fixed prospectively

For the 512 roots, let D be V score minus T score, in [-1,1]. Report its mean and the original conservative finite-randomization envelope with half-width `sqrt(2*log(40)/512) = 0.12004035`. This conditions on fixed slot potential outcomes, independent within-root allocation and no cross-request interference. Correlated source content does not turn the fixed corpus into an IID paper population; unknown provider/service state still threatens no-interference and reproducibility. This is a conditional finite-battery analysis, not an unconditional population confidence certificate.

No primary p-value is required or selected after seeing results. Secondary R contrasts, per-mode/source scores, error acceptance, false rejection, unjustified abstention, tokens and time are descriptive. No significance shopping, alternative primary endpoint selection, optional extension, or outcome-based source removal. Report every prespecified source/mode breakdown; do not promote the most favorable one.

An operationally clean content-format failure gets root score zero and remains in the denominator. An infrastructure/identity/unknown-usage/cleanup failure is **not** zero: stop new admissions, retain HOLD and the full fixed schedule, with missing-arm scores ranged over [0,1]. `contrast_bounds` implements the full-denominator bounds. Do not claim original complete acceptance or manufacture a confirmatory result from an incomplete run. No retries, slot replacements, reserve substitution or automatic protocol amendment.

The previous C08-A HOLD, its unknown residual identity and all previous Luna results remain unchanged. A new study cannot close missing original-paper run provenance or human external validation.

## 7. Power, practical relevance and launch gate

`power.json` reports a distribution-free design calculation, not observed method efficacy. For a true finite-battery gain delta, the stated assumptions give a power lower bound of `1-exp(-N*(delta-margin)^2/2)` when delta exceeds the margin. To make that bound at least 80%, N is at least `ceil(2*(sqrt(log(40))+sqrt(log(5)))^2/delta^2)`.

At N=512 the 95% conditional half-width is **12.004pp**. The power lower bound is about **80.54% if the true gain is 20pp**, not if it is 10pp. A 10pp gain needs 2,035 root blocks for this deliberately conservative 80% bound; the current eligible source frame cannot supply them. A zero lower bound is not a prediction of zero actual power. The calculation is conservative and alternatives could be designed before new outcomes, but no narrower IID interval is silently substituted here.

An author-selected minimum practically useful gain is still needed before a formal study is accepted. Do not choose 20pp merely because it fits the sample budget or pretend the previous headings effect estimates the new workflow effect. A positive interval lower bound establishes only the stated conditional positive-effect claim; to establish a true effect above a practical threshold, the lower bound itself must exceed that threshold. A positive point estimate alone is insufficient.

If the aim is to certify a modest ~10pp advantage with an 80% worst-case power bound, **do not launch this 512-root version as adequate**. Either acquire genuinely additional units under a new prespecified frame, adopt a justified different design before outcomes, or retain the result as a bounded, limited-precision test.

## 9. Reviewer objections and kill criteria

1. These are controlled finite contracts, not blinded natural-paper errors. Narrow claims accordingly.
2. The same assistant authored methods, templates and both oracles. No independent researcher validation is claimed.
3. Main evidence is one archive and transfer only one additional feature dataset. No broad generality claim.
4. Generic T can use joins; if V has no genuine procedural difference, the efficacy story fails. It is not rescued by renaming checks or weakening T.
5. Wide conservative uncertainty and unverified service-state assumptions can prevent certification. More retries are not a solution.

If the oracle paths disagree, stop preparation. If a trivial fixed/one-hop diagnostic solves all cases, stop and do not launch this battery as meaningful. If inputs leak private answers or source labels, stop. If a new experiment is nonpositive, zero-crossing, error-tradeoff harmful or composition-sensitive, retain that outcome and withdraw the corresponding superiority claim. Do not add models/cases until a favorable result appears.

## 10. Prospective statistical-fallacy checklist (11/11 considered)

Composition/Simpson: separate primary and source-transfer estimands. Ecological inference: no population-paper/human claim. Selection/Berkson: explicit distinguishable-pair convenience frame. Collider: retain engineering missingness and full denominator. Base rates: report constructed query label counts, not natural prevalence. Regression to mean: no selected old low scorers or pre/post improvement claim. Survivorship: retain every admitted attempt and its cost. Multiple search: one primary contrast. Forking paths: frozen new proposal, old findings disclosed, no third-party preregistration claimed. Correlation/causation: conditional randomization assumptions and provider-state limits explicit. Reverse causality: no new answer exists before case/card/reference freeze.

These are design risk checks, not evidence that every risk has been eliminated.
