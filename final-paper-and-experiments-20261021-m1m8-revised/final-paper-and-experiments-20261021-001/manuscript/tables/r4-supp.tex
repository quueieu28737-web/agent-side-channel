\section{Real-Agent Evaluation with Training-Only Calibration (E9)}\label{sec:r4}

\subsection{Cohort and execution}

We froze a 115-task protocol with two prompt arms and three repetition identifiers (690 planned episodes). The fixed split assigns 69 tasks from 29 customers to training and 46 tasks from 24 disjoint customers to testing. All 414 training episodes completed before defense calibration was frozen and test inference began. At the publication cutoff, 2026-10-23 10:01:03 UTC, 663 episodes were complete: 414 training and 249 test episodes. Primary comparisons include every test task with all six prompt/repetition cells complete: 41 tasks from 22 customers, 246 episodes. Task 105 contributes three additional completed episodes, retained in the release and reported below. The remaining 27 runs were incomplete. This operational completion cutoff was adopted before the present attack analysis; it did not filter on reward, status or leakage. It is an interim sample, and completion order can affect its task composition.

GPT-6.1 Sol with low reasoning effort supplies the planner and a separate user simulator through Codex app-server. The planner receives the retail policy, public tool schemas, interaction history and actual sandbox observations, and emits one structured action at each step. Reference actions and reward targets are used only for scoring. Each model decision has a fresh ephemeral context without host tools or a host environment. The harness executes decisions in the pinned public retail simulator. Repetition identifiers are cache namespaces, not provider random seeds. The alias is mutable; temperature and an immutable weight snapshot are unavailable. This is a structured-action LLM agent evaluation, not a native function-calling API benchmark.

\subsection{Prompts and defense calibration}

The baseline prompt is the retail policy. The rules prompt adds one customer-details read after identification and before order access, an order read before each order write, and avoidance of unnecessary repeated reads. It preserves authorization and task requirements and prohibits unrelated operations for hiding intent. We compare both prompt arms under raw transport, padding only, online shape cover only, and joint shape cover with constant framing.

Only training trajectories from both prompts determine the shared per-tool count maxima, donor pools and size caps. Donor calls exclude the active customer. Request caps are the largest training request plus four bytes rounded to a 256-byte multiple; response caps use the training 95th percentile plus four bytes rounded to a 1024-byte multiple, including training donor responses. The frozen caps are 1,024 and 3,072 bytes. The online dispatcher can use only past real-call counts; it inserts a shadow call with probability 0.6 when a deficit exists and flushes remaining deficits at episode end. Overflow calls pass through; oversize messages expand to a 1024-byte bucket. Underfill and overflow are reported. Test data never recalibrate these parameters.

Shadow calls execute on a cloned initial database, with observations hidden from the planner. Real calls remain unchanged. Each realized trajectory is reused across the four program conditions, so reward equality across those conditions is structural. The experiment measures call and byte costs, not online delay or feedback-induced utility changes. A byte-transparent relay captures TLS~1.2 loopback replay of actual model-generated requests and sandbox responses; provider traffic and its timing are outside this measurement.

\subsection{Attackers and uncertainty}

The fixed suite contains a training-majority baseline, clean-trained gradient boosting, defense-trained logistic regression and gradient boosting, a dispatch count rule, and network size-decoding learners and rules. All fitted parameters, thresholds and decoder tables use training data only. Targets are cancellation and return intent from the reference task, while planner task reward is scored separately from final database equality and required response strings. Failed tasks and handoffs remain in the cohort. Points weight tasks equally; each primary task has three repeats per prompt. Intervals use 2,000 common customer-cluster bootstrap draws, retaining all of each customer's tasks and repetitions together and recomputing the suite maximum in each draw. They condition on fitted attackers; training, feature-search and unknown-attacker uncertainty are outside their scope. Prompt contrasts pair tasks and repeat identifiers, not identical conversations or model randomness.

\subsection{Interpretation and reproducibility}

E9 supplies real model-generated trajectories and a fully training-calibrated defense evaluation, extending the reference-program tests. Its scope is one public benchmark and one provider model alias, with the same model family supplying the user simulator. All 115 tasks had been available during earlier paper development; the customer holdout is an internal evaluation, not an external benchmark. The incomplete late-task cohort and small positive-customer counts limit extrapolation. An independent human replication remains future work.

The primary analysis contains 11002 model decisions and 2,640 TLS sessions. Records for all 663 completed episodes are retained. The release verifies inference fingerprints, original runtime and pretest analysis hashes, training-only recalibration, sandbox state and required-output scoring, cover reconstruction, TLS accounting, saved predictions, sklearn point metrics and clustered intervals. This is executable verification, not independent external replication.

\path{experiments/sp2027-r4-snapshot-20261023/} contains the cutoff amendment, complete episode membership, original pretest sources, derived analysis, calibration, compressed model records, predictions and validation receipt. Earlier Luna pilots and interrupted attempts are separately archived and excluded. Operational logs and recovery details are retained in the artifact README rather than used as scientific outcomes.
