\section{Implications, Ethics and Limits}\label{sec:agenda}
\subsection{Deployment paths and reporting obligations}\label{sec:deployment}
Shadow state specifies an execution contract with three implementation paths. \textbf{(1) Authorized reads and verified no-ops} can use the live backend with responses discarded; idempotence alone does not preserve state, and read cover cannot hide an exposed write type. \textbf{(2) Provider-supported isolation} can use Kubernetes server dry-run, isolated Stripe sandboxes or transactional rollback \cite{kubernetesdryrun,stripesandboxes,postgresrollback}. These have distinct semantics: dry-run validates without persistence, sandboxes maintain separate state, and rollback covers transactional effects; sequence changes can survive rollback \cite{postgressequences}. \textbf{(3) A trusted MCP/tool gateway} can decrypt an authenticated cover marker and route shadow writes to an isolated local simulator. Real and cover traffic share an ingress envelope; routing, timing and response sizes must not reveal the branch. This is a deployment design, not a measured production integration.

The gateway protects its client-facing link and potentially a relay that cannot access markers or routing. A relay that learns the branch, the gateway itself and a provider observing committed writes require different protection. S17 maps these boundaries and implementation requirements. Across paths, report protected state, exposed observations, training calibration, adaptive attackers and the joint leakage--cost frontier; include latency, backend quotas and every exposed downstream link.

\subsection{Ethics and artifact scope}\label{sec:ethics}
Tool executions and traffic captures use cloned public benchmark databases and local loopback sockets. E9 sends public benchmark instructions and simulated interactions to the model service; it modifies no production tool or real account. Shadow cover requires a trusted isolation boundary. Other-account cancellation is a simulator control. Live deployment requires authorized cover resources and bounded side effects. Bot-detection evasion has a different objective and authorization boundary \cite{zhu2026turing,jeong2026wra}.

The artifact preserves sources, raw observations, structured model decisions, frozen calibration and executable checks. AI-assisted implementation and manuscript revision do not constitute independent validation. The paper distinguishes saved-output replays, real model-generated trajectories and local TLS measurement.

\subsection{Threats to validity}
The purposive corpus and query overlaps do not estimate field-wide recall. Coding agreement and the 24-case rule-application check characterize the archived annotation workflow. Independent recoding, held-out comparisons with simpler review procedures, and independent screening of the 617-record second search remain follow-up validation targets.

E5 uses 48 saved outputs and a proxy tokenizer; E6/E7 use reference programs with known-population calibration. E9--E12 cover one public retail environment and one mutable model alias, also used for user simulation; earlier development had access to all 115 tasks. Cross-fitting expands customer coverage within the same population, and intervals condition on fitted attackers. Program conditions reuse trajectories, so equal reward is structural. External replication, broader model/environment transfer, provider-traffic measurement and interactive latency/feedback effects are the next evaluation targets.
