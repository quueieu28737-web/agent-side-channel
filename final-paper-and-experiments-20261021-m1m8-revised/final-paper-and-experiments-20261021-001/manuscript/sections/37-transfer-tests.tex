We retain artifact identifiers: E1/E3 cover buffered transport and adaptive fitting (\S8.1; S11), E2 tests state-preserving cover (\S8.2; S9/S11), E5--E7 isolate streaming and dispatch mechanisms, E8 tests stand-in planners (S13), E9--E12 analyze real-agent trajectories, E13 measures live tool timing/full tunnels, E14 strengthens attacks and compares classical WF adaptations, and E15 adds same-provider model trajectories. Seven author-constructed mechanism checks were recorded before E5--E7 (S12); they are engineering checks rather than a sample of external review decisions.

For E6/E7/E9, a cell meets the \emph{evaluated-suite criterion} when maximum BA has an upper 95\% bound below 0.60 and maximum AUROC is below 0.65. This absolute-threshold assessment is separate from the measured reduction relative to undefended transport: a lower BA bound above 0.60 indicates above-threshold leakage, while an interval crossing 0.60 leaves the absolute threshold inconclusive. We recompute the suite maximum within each of 2,000 common bootstrap draws: tasks for E6/E7 and customers for E9, retaining their tasks and repeats together. Intervals condition on fitted predictions and do not cover unknown attackers.

\subsection{Transport: buffered and streaming emitters}
The buffered tests use brief/expanded saved responses for 24 topics (12 training, 12 test). A two-link TLS replay remains 100\% separable on the terminal link when only upstream traffic is padded; padding both reduces verbosity inference to 50\%, reproducing NetEcho's mechanism~\cite{netecho2025}. A training-fitted cap reaches 50\% at 2.18$\times$ bytes. Defended-data fitting recovers 13.5--50.0 points under offsets, buckets and random tails (S11).

E5 emits the same 48 texts as per-token server-sent events over TLS~1.2/1.3, reflecting the streaming surface~\cite{weiss2024prompt,whisperleak2025}. Per-event padding preserves token count: verbosity remains 100\% separable. Eight-token batching cuts bytes to 0.21$\times$ and clean-trained BA to 50\%, but refitting recovers 100\%. Constant shape reaches 50\% at 2.42$\times$ bytes and 208 versus 105 token intervals; two overflowing test outputs remain identifiable. Table~\ref{tab:transfer-streaming} gives all emitter, attacker and cost cells. A buffered cap delays the first byte until generation ends, so its cost cannot price streaming protection.

\subsection{Execution: state scope and randomized cover}
\paragraph{State scope}
In the 115 public retail programs, same-item modification changes status and appends a refund even when item and price are unchanged (173/291 pre-insertion units). State preservation $f(s,a)=s$ therefore differs from idempotence $f(f(s,a),a)=f(s,a)$. Cancelling another user's order changes the shared database. Shadow cover separates an observable call from its live effects: authorized reads, noncommitting API operations or a trusted gateway's isolated executor can supply this boundary (\S9.1). A known-position cover call remains removable with 100\% accuracy (S11).

\paragraph{E6: randomized cover against policy-aware attackers}
E6's dispatch observer sees ordered tool names and response lengths. Cover is sampled from other users' programs, randomly interleaved and executed on shadow state, with live execution as a control. Policies add cancellation, pad its count, interleave decoy programs or equalize every tool's count. Templates, donors and caps use all 115 reference programs: this is known-population defense calibration. Attackers use clean/defended gradient boosting and logistic regression on counts, bigrams and lengths, plus a count rule. Task-grouped 5-fold evaluation uses three seeds and cancellation/return targets (18/32 positive tasks).

Table~\ref{tab:r7-e6} reports all dispatch policies. One cancellation drives undefended-data-trained BA to 50\%, but refitting recovers 100\% (P2; full table in S12). Count equalization defeats the count rule while correlated tools yield 76.9\% (P4). Decoy programs, the read-only pattern of WRA \cite{jeong2026wra}, leave 83.5--91.9\%. Shape equalization reaches 50.0\%/54.5\% at 6.7 extra calls per real call. Database equality is 100\% for shadow execution and 0\% for live cancellation, demonstrating the importance of the execution boundary.

\subsection{E7: composing execution and transport on the agent--tool link}
E7 composes dispatch and transport on an encrypted agent--tool link (Figure~\ref{fig:system-model}). Four cover policies yield 4,140 TLS~1.2 sessions. Framing is undefended, 1024-byte buckets or constant requests/responses with overflow buckets. The evaluated network projection contains direction-tagged TLS record lengths and order; it excludes tool names and inter-arrival times. A profiling attacker learns size-to-tool mappings from training-fold API calls and applies dispatch attacks to decoded traces; S12 specifies caps and classifiers.

Request-only tool identification reaches 89.9\%/91.4\% under cancellation/return folds (582 calls; majority 29.4\%). Count and decoy cover leave 72.7--95.7\% network BA, extending their dispatch leakage (P5). Framing alone leaves bucketed return BA at 73.9\%. Shape cover gives 51.2\%/60.5\% with undefended framing and 54.4\%/50.0\% with constant framing. No configuration meets the absolute criterion for both targets. Joint constant framing costs 26.3$\times$ bytes and 7.7$\times$ calls with 100\% database equality: one operating point, not a minimum cost (P7). E8's stand-in planners (S13) motivate the causal, training-only dispatcher evaluated next with real model decisions.

\paragraph{Transport link versus dispatch boundary}
Per-call framing leaves call counts and turn structure exposed. A full traffic-flow-confidentiality tunnel can instead conceal these from a passive link observer using fixed-size, constant-rate traffic \cite{rfc9347}; protecting session duration additionally requires a workload-independent traffic horizon. Its dummy packets need not execute tools. E7/E9 test per-call framing; E13 separately measures a complete fixed-rate TLS tunnel. At a dispatch boundary that exposes calls after decapsulation, transport padding is removed and call-level cover becomes relevant. Protection then depends on hiding cover markers and downstream routing from that observer (S17).

\subsection{E9: real agents and training-only defense calibration}\label{sec:real-agent}
E9 tests defense reuse on autonomous model-generated trajectories under a strict calibration boundary. GPT-6.1 Sol (low reasoning effort) plans and responds from the retail policy, public tool schemas and actual sandbox observations. A separate context of the same model simulates the user. The rules arm adds one customer-details read before order access and a read before each order write. All 115 tasks have two prompt arms and three repeats, completing the frozen 690-run protocol. All 414 training runs on 69 tasks precede freezing of a shared count template, donor pools and framing caps; the 276 test runs cover 46 tasks from 24 disjoint customers.

\paragraph{Planner-visible equivalence}
Let $H$ be the planner's message/tool-observation history, excluding wall-clock timing. Real calls and responses pass unchanged; cover uses isolated state and hidden responses. Thus the planner projection satisfies $\pi_{\rm plan}(D(H))=H$ (Appendix~\ref{app:equivalence}). E9 replays each realized trajectory through four program conditions, isolating the program-layer effect from LLM sampling variation. Online denotes prefix-only scheduling; this equivalence does not preserve elapsed time, queueing or timeout behavior. The trusted cover executor knows which calls are shadow calls; E9 protects the measured dispatch/network projections, not this executor or a provider's commit log.

The dispatcher inserts training-derived cover using only past calls and flushes unmet counts at episode end. A timing-aware observer could exploit this flush or read/write service times; E9 measures the length/order projection, not a defense against that observer. Four program conditions per prompt isolate undefended transport, padding, shape cover and their combination. Training-fitted attackers evaluate dispatch and network observations across 2,760 TLS replay sessions. Every test task, failure and handoff remains in the analysis. Supplement S14 supplies the full ablations and customer-cluster intervals.

\subsection{E10--E12: cross-fitting, operating points and mechanism}\label{sec:r5}
\paragraph{E10: primary within-cohort summary (post hoc)}
A post hoc customer-grouped stratified 5-fold analysis reuses all 690 runs: 53 customers, including 14 cancellation-positive and 18 return-positive customers. Each fold fits defense templates, donors, caps and attackers on the other customers only. Its analytic TLS~1.2 model matches all 2,760 measured sessions and 120 fresh captures. We expand all nine prior attacks with a trained 1D-CNN and k-FP-style forest-leaf attack; the primary table uses the maximum over all 11. Undefended BA is 91.7\%/85.5\%. Recalibrating the joint shadow-count/constant-framing design reduces BA by 31.2/30.0 points (paired 95\% intervals [15.3,41.0]/[14.8,39.2]); joint buckets reduce it by 34.6/32.8 points. Stronger learners preserve these reductions while increasing some defended estimates. Both joint designs leave the absolute criterion inconclusive (S21).

\paragraph{E11: choosing the operating point}
The historical E11 selection uses the original suite and six configurations. Choosing the cheapest point with all four inner-fold BAs $\leq60\%$, using only the original 69 training tasks, picks 1024-byte buckets. \paragraph{E12: locating the signal}
The expanded 11-attack oracle ablation (Table~\ref{tab:r7-e12}) retains 91.7\%/84.9\% BA in state-changing exchanges, which comprise only 19.6\% of real tool calls. Removing them reduces BA to 62.8\%/59.9\%: paired decreases of 28.9 [10.7,41.9] and 25.6 [11.0,35.4] points. Writes therefore carry the dominant measured signal, while reads retain residual information. Rules reduce distinct read sequences from 74 to 62, while write sequences remain 37 versus 36. The oracle selects exchanges using true tool types, then exposes only their network lengths/order; it is a localization diagnostic, not a deployable filter.

\subsection{E15: an additional model on the same environment}
A separate 150-run GPT-6 Luna/low study uses 75 existing retail tasks, two prompts and one repetition; ten pilots are excluded. Under the standard prompt, a three-model dispatch diagnostic gives writes-only BA of 87.5/66.6\%, versus 50.0/57.0\% for get/find/list reads. The rules arm likewise retains more measured signal in writes. Task rewards are 32/75 and 33/75 for standard/rules; all failures and seven protocol-error episodes remain included. Each prompt-specific attacker fits only 29 training episodes, and the inherited gradient booster cannot split at this sample size. This smaller-suite, same-provider check supports the write-associated pattern without establishing cross-environment transfer. Padding alone matches or improves the joint network point estimates here. S22 gives every cell, actual elapsed times, the distinct read-view definition and 600 local TLS replays with training-only calibration.

\subsection{What the cases establish}
The experiments test the comparison obligations. E5 ties protection to the emitter; E6/E7 tie cover to state and the final network view; E9--E12 locate the write-associated signal and price training-calibrated shaping. E13 exposes the clock and tool-response cost. E14 tests stronger learners and established WF mechanisms on the same saved workload; E15 checks a separate model alias. The supported outcome is a measured trade-off under explicit observation and execution contracts, not an absolute security bound or a novel padding construction.
