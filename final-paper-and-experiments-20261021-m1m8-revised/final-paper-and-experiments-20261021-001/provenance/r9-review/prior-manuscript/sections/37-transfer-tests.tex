\section{Controlled Transfer Tests}\label{sec:controlled-placement}\label{sec:tau-cover-bridge}
The experiments connect observation, execution and matched evaluation. We retain artifact identifiers: E1/E3 cover buffered transport and adaptive fitting (\S8.1; S11), E2 tests state-preserving cover (\S8.2; S9/S11), E5--E7 isolate streaming and dispatch mechanisms, E8 tests stand-in planners (S13), E9--E12 analyze real-agent trajectories, E13 measures live tool timing/full tunnels, E14 strengthens attacks and compares classical WF adaptations, and E15 adds same-provider model trajectories. S18 gives the full concordance, including unused E4. We use \emph{undefended} for transport without a program defense, and \emph{standard prompt} for the prompt arm called \texttt{baseline} in immutable data. Artifact keys \texttt{raw}/\texttt{baseline} are retained for reproducibility. Seven author-constructed mechanism checks were recorded before E5--E7 (S12); they are engineering checks rather than a sample of external review decisions.

The original E6/E7/E9 protocol uses an author-chosen \emph{evaluated-suite criterion} when maximum BA has an upper 95\% bound below 0.60 and maximum AUROC is below 0.65. It is an engineering screening rule, not a cryptographic definition or a field-standard acceptable-risk threshold. We retain it for protocol accountability, not as the paper's contribution. A measured reduction alone cannot demonstrate that a deployment is protected: a lower BA bound above 0.60 indicates above-threshold leakage, while an interval crossing 0.60 leaves the absolute threshold inconclusive. We recompute the suite maximum within each of 2,000 common bootstrap draws: tasks for E6/E7 and customers for E9, retaining their tasks and repeats together. Intervals condition on fitted predictions and do not cover unknown attackers.

\subsection{Transport: buffered and streaming emitters}
The buffered tests use brief/expanded saved responses for 24 topics (12 training, 12 test). A two-link TLS replay remains 100\% separable on the terminal link when only upstream traffic is padded; padding both reduces verbosity inference to 50\%, reproducing NetEcho's mechanism~\cite{netecho2025}. For TLS 1.2, a training-fitted buffered cap reaches 50\% at 2.18$\times$ bytes; Table~\ref{tab:transfer-streaming} uses TLS 1.3 and its own denominator (2.19$\times$). Defended-data fitting recovers 13.5--50.0 points under offsets, buckets and random tails (S11).

E5 emits the same 48 texts as per-token server-sent events over TLS~1.2/1.3, reflecting the streaming surface~\cite{weiss2024prompt,whisperleak2025}. Per-event padding preserves token count: verbosity remains 100\% separable. Eight-token batching cuts bytes to 0.21$\times$ and clean-trained BA to 50\%, but refitting recovers 100\%. Constant shape reaches 50\% at 2.42$\times$ bytes and 208 versus 105 token intervals; two overflowing test outputs remain identifiable. Table~\ref{tab:transfer-streaming} gives all emitter, attacker and cost cells. A buffered cap delays the first byte until generation ends, so its cost cannot price streaming protection.

\subsection{Execution: state scope and randomized cover}
\paragraph{State scope}
In the 115 public retail programs, same-item modification changes status and appends a refund even when item and price are unchanged (173/291 pre-insertion units). State preservation $f(s,a)=s$ therefore differs from idempotence $f(f(s,a),a)=f(s,a)$. Cancelling another user's order changes the shared database. Shadow cover separates an observable call from its live effects: authorized reads, noncommitting API operations or a trusted gateway's isolated executor can supply this boundary (\S9.1). A known-position cover call remains removable with 100\% accuracy (S11).

\paragraph{E6: randomized cover against policy-aware attackers}
E6's dispatch observer sees ordered tool names and response lengths. Cover is sampled from other users' programs, randomly interleaved and executed on shadow state, with live execution as a control. Policies add cancellation, pad its count, interleave decoy programs or equalize every tool's count. Templates, donors and caps use all 115 reference programs: this is known-population defense calibration. Attackers use clean/defended gradient boosting and logistic regression on counts, bigrams and lengths, plus a count rule. Task-grouped 5-fold evaluation uses three seeds and cancellation/return targets (18/32 positive tasks).

Table~\ref{tab:r7-e6} reports all dispatch policies. One cancellation drives undefended-data-trained BA to 50\%, but refitting recovers 100\% (full table in S12). Count equalization defeats the count rule while correlated tools yield 76.9\% . Decoy programs, the read-only pattern of WRA \cite{jeong2026wra}, leave 83.5--91.9\%. Shape equalization reaches 50.0\%/54.5\% at 6.7 extra calls per real call. The replay checker confirms the designed state invariant in all shadow cases; live cancellation violates it in every case. This checks implementation conformance, not live planner performance.

\subsection{E7: composing execution and transport on the agent--tool link}
E7 composes dispatch and transport on an encrypted agent--tool link (Figure~\ref{fig:system-model}). Four cover policies yield 4,140 TLS~1.2 sessions. Framing is undefended, 1024-byte buckets or constant requests/responses with overflow buckets. The evaluated network projection contains direction-tagged TLS record lengths and order; it excludes tool names and inter-arrival times. A profiling attacker learns size-to-tool mappings from training-fold API calls and applies dispatch attacks to decoded traces; S12 specifies caps and classifiers.

Request-only tool identification reaches 89.9/91.4\% under cancellation/return folds (582 calls; majority 29.4\%). Framing alone leaves bucketed return BA at 73.9\%. Joint shape cover with constant framing gives 54.4/50.0\% at 26.3$\times$ bytes and 7.7$\times$ calls; no condition meets the two-target criterion. S12 gives all policies, and S13 retains E8's stand-in-planner comparison.

\paragraph{Transport link versus dispatch boundary}
Per-call framing leaves call counts and turn structure exposed. A full traffic-flow-confidentiality tunnel can instead conceal these from a passive link observer using fixed-size, constant-rate traffic \cite{rfc9347}; protecting session duration additionally requires a workload-independent traffic horizon. Its dummy packets need not execute tools. E7/E9 test per-call framing; E13 separately measures a complete fixed-rate TLS tunnel. At a dispatch boundary that exposes calls after decapsulation, transport padding is removed and call-level cover becomes relevant. Protection then depends on hiding cover markers and downstream routing from that observer (S17).

\subsection{E9: real agents and training-only defense calibration}\label{sec:real-agent}
E9 tests program transforms of autonomous model-generated trajectories under a frozen calibration boundary. Its targets are whether the task's reference program requests \texttt{cancel\_pending\_order} or \texttt{return\_delivered\_order\_items}; they are fixed before execution, not inferred from the realized trajectory. They nonetheless encode intended operation types, so identifying their writes is an expected diagnostic, not evidence of latent-content leakage. GPT-6.1 Sol (low reasoning effort) plans and responds from the retail policy, public tool schemas and actual sandbox observations. A separate context of the same model simulates the user. The rules arm adds one customer-details read before order access and a read before each order write. All 115 tasks have two prompt arms and three repeats, completing the frozen 690-run protocol. All 414 training runs on 69 tasks precede freezing of a shared count template, donor pools and framing caps; the 276 test runs cover 46 tasks from 24 disjoint customers.

\paragraph{Planner-visible equivalence}
Let $H$ exclude wall-clock timing. Passing real calls/responses unchanged while isolating cover state and hiding cover responses gives $\pi_{\rm plan}(D(H))=H$ (Appendix~\ref{app:equivalence}). Reusing a trajectory isolates the transform from LLM sampling, but does not preserve queueing, timeouts or replanning. Prefix-only scheduling is online; trajectory collection is not repeated under each defense. The trusted executor knows cover identities and is outside the protected projection.

The dispatcher inserts training-derived cover using only past calls and flushes unmet counts at episode end. A timing-aware observer could exploit this flush or read/write service times; E9 measures the length/order projection, not a defense against that observer. Four program conditions per prompt isolate undefended transport, padding, shape cover and their combination. Training-fitted attackers evaluate dispatch and network observations across 2,760 TLS replay sessions. Every test task, failure and handoff remains in the analysis. Supplement S14 supplies the full ablations and customer-cluster intervals.

\paragraph{Behavioral control and frozen-split reference}
Rules raise mechanical read-order adherence from 86.2\% to 97.1\%, while undefended intent BA remains above 93\%. This read-order control is not a privacy defense. Rewards are 110/138 versus 105/138 (paired difference $-3.6$ points, interval $[-9.5,1.4]$). Program conditions inherit these rewards from reused trajectories; defended planner utility is not remeasured.

The frozen joint-shaping cell has chance-level point estimates, with upper bounds 60.6\%/65.5\%; the absolute criterion is unconfirmed. The paired decreases are 47.2/44.0 points. Rules plus joint shaping leaves return BA at 60.6\%, demonstrating sensitivity to the prompt/cohort realization. Five cancellation-positive and seven return-positive test customers limit precision. The following all-customer comparison is exploratory. E9 retains its original calibration chronology; neither analysis is a new-customer confirmation, since the full task population was available during development.

\subsection{E10--E12: cross-fitting, operating points and mechanism}\label{sec:r5}
\paragraph{E10: exploratory within-cohort comparison}
A post hoc customer-grouped stratified 5-fold analysis reuses all 690 runs: 53 customers, including 14 cancellation-positive and 18 return-positive customers. Each fold fits defense templates, donors, caps and attackers on the other customers only. Its analytic TLS~1.2 model matches all 2,760 measured sessions and 120 fresh captures. We expand all nine prior attacks with a trained 1D-CNN and k-FP-style forest-leaf attack; Table~\ref{tab:r5} uses the maximum over all 11. Undefended BA is 91.7\%/85.5\%. Recalibrating the joint shadow-count/constant-framing design reduces BA by 31.2/30.0 points (paired 95\% intervals [15.3,41.0]/[14.8,39.2]); joint buckets reduce it by 34.6/32.8 points. Stronger learners preserve these reductions while increasing some defended estimates. Neither joint design establishes the original absolute criterion. The paired effects answer whether these transforms reduce this fitted suite's inference, not whether they withstand an arbitrary attacker (S21).

\paragraph{E12: operation-category localization, not content inference}
The expanded 11-attack oracle ablation (Table~\ref{tab:r7-e12}) retains 91.7\%/84.9\% BA in state-changing exchanges, which comprise only 19.6\% of real tool calls. Removing them reduces BA to 62.8\%/59.9\%: paired decreases of 28.9 [10.7,41.9] and 25.6 [11.0,35.4] points. This localization is label-coupled: the target names the intended write operation. It establishes that ciphertext metadata can preserve an operation signature after names are hidden, but not that writes generally reveal unrelated private attributes. Reads retain predictive metadata. Rules reduce distinct read sequences from 74 to 62, while write sequences remain 37 versus 36. The oracle selects exchanges using true tool types, then exposes only their network lengths/order; it is a localization diagnostic, not a deployable filter.

\subsection{E15: an additional model on the same environment}
A separate 150-run GPT-6 Luna/low study uses 75 existing retail tasks, two prompts and one repetition (ten pilots excluded). Standard-prompt dispatch BA is 87.5/66.6\% for writes versus 50.0/57.0\% for get/find/list reads. Rewards are 32/75 and 33/75; seven protocol-error episodes remain included. Each prompt's attacker has only 29 training episodes. This repeats the operation-label diagnostic with a same-provider alias; it is not a second environment or semantic-attribute validation. Padding matches or improves joint network point estimates. S22 gives all cells and 600 TLS replays.

\paragraph{E16: a target independent of operation type}
An exploratory attribute check fixes single-item returns and a pre-fit digital-device product grouping. Each prompt yields 20 customer--order--item instances from only 15 customers; repeats are aggregated and the original customer folds retained. The fixed LR/RF/GB suite gives 30.3\% pooled OOF BA [16.7,52.7], versus 50\% for a constant predictor. A single fixed shuffled target gives 65.2\%; it is not a permutation test. Both prompt arms have identical features. Below-chance scores can reflect reverse associations; this small diagnostic neither confirms non-action-attribute inference nor proves no leakage (S23).

\subsection{What the cases establish}
The experiments test the comparison obligations. E5 ties protection to the emitter; E6/E7 tie cover to state and the final network view; E9--E12 locate operation-category signatures and price training-calibrated shaping. E13 exposes the clock and tool-response cost. E14 tests stronger learners and established WF mechanisms on the same saved workload; E15 checks a separate model alias. The supported outcome is a measured trade-off under explicit observation and execution contracts, not an absolute security bound or a novel padding construction.
