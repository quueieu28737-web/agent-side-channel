# R8：防御公平性与自身证据审计

日期：2026-10-24。此审计只读旧代码、冻结文件、完整结果和已保存预测；未调用 LLM，未训练新攻击者，未修改旧实验或主稿。R1–R9 与正文 family-audit matrix 的定义一致。新增机器可读证据及精确表位于发布包 `provenance/r8-review/defense-self-audit.{py,json,csv,md}`。

## 结论

1. **没有证据支持把 Shadow 写成已证实的通用成功防御。** E9 双目标绝对标准未确认；E13/E14 完整攻击并集同样不支持双目标通过。BA 下降是限定工作负载、观察视图、攻击套件下的实测下降。跨越 .60 的区间应写“不确定”，不能统一写成已证明安全，也不能把所有不通过单元写成显著高于 .60。
2. **共同七攻击器是公平比较的必要条件，不是完整安全评估。** E14 measured 条件另有旧 E13 攻击，其更强并集必须保留。WT、Shadow、隧道的共同七结果见下文；更弱的共同子集不能替换攻击并集以改善 Shadow headline。
3. **本研究自己的 R8 utility 绑定也不完整。** 原生 LLM reward 是实际原始任务结果；复制同一动作到程序防御条件所得 reward 相等是结构继承。E13 的真实响应和最终状态一致是较强的实测逻辑检查，但仍不等于实时 LLM 在延迟、超时、配额、思考和反馈下的任务效用。
4. **flush 不可区分性已失败。** 90.4%/92.3% 是逐 TLS 记录的 flush 状态检测 BA。它不等于恢复原始意图成功率，但表明调度阶段指纹可学习。已经保存“估计边界→剥离后缀→意图攻击”，不能把此实验写成尚未做，也不能声称边界可识别却必然恢复意图。

## 三种容易混淆的效用证据

| 层次 | 实际证据 | 能支持 | 不能支持 |
|---|---|---|---|
| 结构性不变式 | cover 响应不进入planner、shadow独立状态；程序回放沿用同实质动作 | 在模型历史不含时钟且假设执行边界满足时，planner逻辑投影不变 | 无延迟损失、无超时、生产工具安全、完整LLM任务效用 |
| 实测逻辑一致性 | E13逐真实响应比较、最终live DB equality，4140/4140会话通过 | 本地固定动作工具链确实保持这些逻辑输出/状态 | LLM在不同时间、失败、争用、token预算下仍选同下一动作 |
| Live LLM utility | 原Sol任务原生reward；Luna150原生reward和实际elapsed；没有在cover条件重跑planner | 原收集设置的真实任务结果 | “Shadow无utility损失”、WT优于Shadow的在线任务成功、隧道生产部署可行性 |

E14 WT适配 `adapters.transform()` 只对由record长度导出的抽象fragment进行 `kept == range(...)` 与不提前发送断言。它复制 `native_reward`，不是对相应WF防御做task reward重测；应以与Shadow同样严格的口径标注。反过来，E13比WF适配多做了实测逻辑检查，也不能因此跳过 live LLM utility 空缺。

## Flush检测与已执行的“分离后攻击”

`sp2027-r6-timing/analyze.py::detector_data` 用 `t >= marks.flush_start_ns` 标记record；不是“此record是真实还是cover”，更不是cancel/return目标。并行时flush阶段开始与未完cover可能重叠，因此时间阶段标签不等于语义真实性。`features.local_features` 只用全迹观察到的方向/长度/相邻gap、position/time fraction、elapsed/remaining；可离线看完整trace，不是实时online detector。真实边界只用于train监督及test评分，不进入攻击特征。

|---|---|---:|---|
| serial |90.4493 [88.3071,92.4568]%|.966764|15278 records=8902阶段后+6376阶段前；276episodes、24customers，合并两prompt |
| parallel2 |92.3106 [90.6481,93.9077]%|.978665|同15278 records及276episodes/24customers |

独立真实/cover请求检测：serial82.5306%、parallel96.0799%，7639 encrypted requests=5657cover+1982real（同276episodes/24customers）。这进一步反对“掩护不可区分”的强说法；其记录级BA也不能直接替代episode级意图BA。

已有正式方法：训练集414轨迹，每scheduler训练RF80/depth8/leaf5检测器；3-fold customer GroupKFold生成训练record概率的OOF值，避免用self-fit分段训练意图模型；`cutpoint` 以单次pre→flush转折最大似然选边界；保留边界前prefix；其joint特征训练LR/GB/RF加majority。测试用全训练集拟合且在test采集前冻结的RF估计切点。意图模型每arm207train→138test。每cell客户bootstrap2000draw；cancel1988有效、return2000有效。

### 如追加更强分离攻击，先冻结，当前未执行

已有三模型剥离攻击已经回答最直接问题，无需重复拟合后伪装新实验。可选追加为：在**新**分析目录冻结计划与脚本hash；仅用现有R6 captures，不增加LLM或新客户；沿用已有frozen detector/training_cuts/test_cuts而不调切点；用共同七学习器对估计prefix重新拟合（不改变已有模型），原207train/arm与138test/arm；test包含所有空prefix/失败；保留完整未剥离七模型和旧E13并集；主要指标为配对“剥离七+未剥离完整并集”相对原完整并集的BA/AUC增量、同一客户draw内重选max、有效draw及positive客户分母。任何超参、cut rule、seed和CNN截断在读新增test输出前锁定；因旧test已分析，明确post hoc，不称盲测或外部预注册。oracle真边界可另列上界诊断，不能当作可部署攻击。若做cover-vs-real逐record保留，需另定train OOF映射与请求/响应配对规则，不能悄悄以ground truth删除cover。此段只是冻结方案建议，**没有产生新攻击结果**。
