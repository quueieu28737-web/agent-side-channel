## 二、问题 1：新增的两个受控实验能否支撑核心贡献？

**结论：修订前不能。它们只部分支撑三条义务中的两条，对“审计框架有用”这一核心主张没有提供证据。**

1. **TLS 实验测的投影，不是语料中主要攻击使用的投影。** Weiss、Whisper Leak 和 NetEcho 观察的是逐 token 流记录。原实验却在响应生成完后才整体分帧（buffered），用总长度阈值作为攻击者。论文自己的 Check 1 恰好要求“绑定最终发射的投影”，所以 2.18× cap 这个结论按论文自己的规则也属于 *unresolved*，不能迁移到流式部署。
2. **双链路重发实验的结论由构造决定。** 前端解密后重新分块，终端未填充时当然可分。这复现了 NetEcho，并不是证据。
3. **D0/D2 增益是教科书结论。** 13.5–50.0pp 的适应性增益说明“要做适应性评估”，但这在 WF 文献里早已是标准要求。
4. **零售实验中的 cover 是稻草人。** cover 固定插在首尾、动作确定，观察者又能看到工具名，所以计数规则和位置规则 100% 识别是由设计保证的结果。它证明“坏的 cover 是坏的”，却没有回答“设计合理的 cover 能达到什么”，因此撑不起第 9 节的建议。
5. **“same-item write 改变状态”取决于 τ-bench 的一个实现细节。** 这一条可以作为反例保留，但不能写成普遍规律。
6. **两条路径从未组合测试。** 图 1 是全文的概念模型，作者也承认“不是联合测试系统”。实际部署中，远程工具服务器在同一条加密连接上同时承载观察路径和执行路径。
7. **没有检验审计的预测效度。** 24 个场景由作者自建，标签也来自同一批作者，论文自己撤回了“框架有效”的结论。于是“审计→实验”之间只有示例关系，没有检验关系。

**本轮修订后**：E5–E7 分别检验了 7 条在实验前写入并提交的审计判断（`PREREGISTRATION.json`，commit `16f6254` 早于全部实验代码）。结果是 5 条证实、2 条部分证实、0 条被推翻。核心贡献（C2 审计）因此第一次得到可证伪的经验支持。但这仍是同一作者的内部检验，不是外部效度。

## 三、问题 2：现在创新性和实证够了吗？

**创新性（修订后）**
- 已有的：82 家族、39 条记录的结果记录库；R1–R9 审计；“未绑定≠失败”的三态判定。这些属于方法论层面的贡献。
- 本轮新增、可写进贡献的发现：
  1. 缓冲 cap 的成本对象与流式发射不同。逐事件 padding（部署中常见的 obfuscation 字段）下，冗长度仍 100% 可分，48 选 1 的身份识别为 58–62%（随机 2.1%）。达到 50% 的恒定形状流需要 2.42× 字节，完成时间翻倍。
  2. clean-trained D0 会系统性低估泄漏：8-token 批处理下 D0 为 50%，D2 为 100%；p=1 取消 cover 下 D0 为 50%，D2 为 100%。
  3. 在调度视图中被评估的 cover，到了加密工具链路上会因请求大小泄漏：请求大小单独就能识别 95.7% 的调用。只有“沙箱化形状均衡 cover + 恒定帧”的组合接近随机，代价是 26.3× 字节和 7.7× 往返。
- 仍需诚实承认：逐包 padding 保留计数、恒定形状代价高，这些是 WF 文献的已知规律（Tamaraw、WTF-PAD）。本文的增量在于把它们绑定到 LLM 流式和工具链路上的具体迁移判断。正文 4.2 节已加入这一定位。

**实证（修订后）**
- 足够支撑“审计能标出会失败的迁移”这一窄结论。
- 不够支撑任何“推荐防御”或“隐私—效用前沿”的结论。原因有四：E6/E7 的正类只有 18（取消）和 32（退货）个任务，区间宽；数据是 gold 程序重放，没有 LLM planner；token 化是代理；没有时序攻击。

## 五、修改清单与实施步骤

### A 类：本轮已完成（`test` 分支）

**A1. E5：流式发射器迁移检验（对应问题 1 第 1 条）**
1. `tlslab.py`：实现回环 TLS 1.2/1.3 透明中继，只统计握手后的 application record，并关闭 TLS 1.3 ticket。
2. `e5_streaming.py`：把 48 条保存响应以 SSE chunk 逐 token 发射（o200k_base 作代理分词），共 7 种分帧：buffered 原始、buffered cap、逐 token、随机事件 padding、恒定事件、8-token 批处理、恒定事件加计数上限。
3. 攻击者：D0 总字节阈值；D2 总字节/记录数阈值和逻辑回归序列模型；封闭世界 48 选 1 识别，攻击者先独立做一次 profiling 运行。
4. 全部观测来自真实 socket 抓包（不再用字节核算替代），随机策略做 10 次抽样，每次都实测。
5. 锚点检查：buffered cap 复现 2.18×（TLS1.2）和 2.19×（TLS1.3），与第一轮一致。

**A2. E6：随机化 cover 与策略感知攻击者（对应问题 1 第 4 条）**
1. cover 调用从其他用户的参考程序中抽样，位置随机，在每会话沙箱中执行；live 执行作为对照。
2. 7 种策略：p=0.5/1 取消、取消计数补齐到 2、1 或 2 个完整诱饵程序、形状均衡（每个工具补齐到公开程序群体中的最大计数，模板与标签无关）。
3. 攻击者：D0/D2 梯度提升和逻辑回归（特征为计数、bigram、响应长度）以及计数规则。在全部 115 任务 × 3 种子上做任务分组 5 折交叉验证，用任务簇 bootstrap 求区间。
4. 参数在实验前固定，不在测试任务上调参，回应了上一轮“策略在全集上开发”的问题。

**A3. E7：加密 agent–tool 链路上的组合（对应问题 1 第 6 条）**
1. 4 种 cover × 3 种分帧（raw、1024B 桶、恒定），共 4,140 个 TLS 1.2 会话，每次调用一个请求和一个响应。
2. 新增 profiling 解码攻击者：在训练折上学习“大小→工具”表，再把调度视图的攻击用于解码后的轨迹。
3. 输出泄漏、DB 相等、字节倍数和往返倍数。

**A4. 预注册迁移判断（对应问题 1 第 7 条）**
1. 实验前写入 `PREREGISTRATION.json`：P1–P7 的审计判断、依据的检查项和数值阈值（protected：BA 上界 < 0.60 且 AUROC < 0.65；not protected：BA 下界 > 0.60）。
2. `resolve_predictions.py` 按阈值机械判定，并在正文新增 Table 12。
3. “最佳攻击者”取包括 D0 在内所有攻击者的最大值，对防御方偏保守。

**A5. 稿件修改**
1. 副标题改为 “A Result-Record Audit with Pre-Registered Transfer Tests”；摘要和贡献列表重写。
2. 新的第 8 节 “Controlled Transfer Tests”：第一轮结果压缩为两段，完整表格移到 Supplement S11；E5–E7 和预测结果放在正文 Table 10–12；完整区间放在 Supplement S12。
3. 4.2 节删除 “real TLS streams” 的过度声明，并加入与 WF 文献的定位；第 5 节改名为 “Three Literature Case Studies”。
4. 更新 Table 7 最后一列、图 1 题注、第 9 节优先事项、伦理（沙箱需要工具提供方配合）、威胁效度和结论。
5. 正文表格由 `make_tables.py` 从 JSON 直接生成，`verify_r2.py` 校验逐字节一致，防止数字漂移。

**A6. 工件**

## 六、本轮实验结果摘要

| 预测 | 判断 | 结果 |
|---|---|---|
| P1 buffered 2.18× cap 能迁移到流式 | Unresolved→Incompatible | 证实：逐事件 padding 下 T1 为 100%；恒定形状 2.42× 字节，完成时间 208 vs 105 个 token 间隔 |
| P2 批处理下 D0 低就说明有保护 | Unresolved (R5) | 证实：D0 50% / D2 100%；p=1 取消 cover 下 D0 50% / D2 100% |
| P3 逐事件 padding 能阻止识别 | Unresolved→Incompatible | 证实：识别 58–62%，随机 2.1% |
| P4 取消计数均衡能隐藏取消 | Unresolved→Incompatible | 证实：计数规则 50%，学习器 76.9% [65, 88] |
| P5 调度 cover 能保护工具链路 | Unresolved | 证实：请求大小识别 95.7% 的调用；BA 72.7–95.7% |
| P6 仅传输分帧能保护意图 | Unresolved→Incompatible | 部分证实：桶分帧下退货为 73.9% [65, 83]，其余格 53.6–60.1% 不确定 |
| P7 组合能保护且不损坏 DB | Unresolved | 部分证实：退货 50.0%，取消 54.4% [47, 62]（上界比阈值高 1.7pp）；DB 100%；26.3× 字节，7.7× 往返 |

复跑方式见 `experiments/sp2027-r2/README.md`。本轮没有模型调用，也没有生产服务或外部网络访问。
