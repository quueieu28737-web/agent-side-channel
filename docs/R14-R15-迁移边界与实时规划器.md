# R14–R15：防御效果迁移边界与实时 planner

## 本轮完成范围

- MiniMax-M3 与 GLM-5.3-flash 各 115 次正式任务，均完成原始请求、轨迹、奖励、校准和 TLS 定位验证；预试验整体保留且不混入正式样本。
- 两模型攻击器迁移矩阵、校准迁移矩阵，以及仅写操作整形：690 次实际本地 TLS 捕获，28 行七攻击套件结果。七攻击包含原 endpoint 六攻击及总交换计数；不冒充 Sol 的 timing/CNN 更大套件。
- 非 oracle 写检测及下游推断保存预测并复算；请求字段长度分解保留无效工具别名的独立行。
- 实时 planner：50 个既有任务 × 两臂，100/100 完成。基线与 prefix-shadow 都实际调用模型；不复用原始 R12 planner 轨迹。

## 主要真实结果

| 对照 | 取消 / 退货 BA（%） | 范围 |
|---|---:|---|
| MiniMax 自身原始 → 联合整形 | 58.3 / 83.5 → 60.4 / 67.5 | 扩展七攻击，模型内对照 |
| GLM 自身原始 → 联合整形 | 100.0 / 86.6 → 50.0 / 67.3 | 同上 |
| MiniMax 校准 → GLM | 70.8 / 50.0 | 目标模型训练客户重新拟合攻击器 |
| GLM 校准 → MiniMax | 50.8 / 63.0 | 同上 |
| MiniMax 仅写填充 | 50.0 / 61.3 | 1.45× 字节 |
| GLM 仅写填充 | 60.0 / 61.6 | 1.51× 字节 |

MiniMax→GLM 校准相对 GLM 自身校准的取消差值为 +20.8 点，客户配对区间 [-12.6,35.3]；退货为 -17.3 点，区间 [-38.2,-5.3]。因此不能把点估计的方向变化全部称为显著差异，也不能按单一 BA 给模型排序。

源训练攻击器迁移到另一模型的无防御退货 BA 为 77.5% / 88.1%。非 oracle 写检测的精确率/召回率为 MiniMax 34.9%/96.3%、GLM 98.3%/89.4%；oracle 定位不等于攻击者能可靠选择对应交换。

## 实时效用与接续修复

基线成功 37/50，prefix-shadow 33/50，配对差值 -8.0 点，37 个客户的 2,000 次聚类 bootstrap 区间 [-23.9,6.5]。两臂各有 12 次注入工具响应超时；超时后分别继续 96/93 个工具动作。终止协议错误 11/7 均保留在分母。Prefix-shadow 实际执行 390 个隔离 cover 调用。

本实验是 prefix-shadow 调度器加模拟响应延迟/截止故障：没有 terminal flush、恒定 TLS framing 或真实 WAN。它补上该调度器的闭环效用证据，不为原 Exp 3 完整联合防御继承 reward。最终执行遍历记录的响应等待 p95 为 32/47 ms，排除模型生成与 WAN，并包含缓存接续重放；GetTickCount64 的 15.625 ms 分辨率已披露。

97/100 时定位到导入顺序错误：运行时误载共享 adapter，沿用 180 秒等待。显式加载本地 600 秒 adapter 后完成最后三次。请求体、推理配置、解析及已有缓存保持不变；原始错误、代码版本和修订记录完整保留。校验器原先假定 20 ms 等待必然被记录为至少 19 ms，与实际时钟分辨率不符；修正为一 tick 容差并逐行重算计划截止规则，没有更改测量记录。
