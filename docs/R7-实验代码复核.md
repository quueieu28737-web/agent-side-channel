# R7 robustness 实验代码与证据复核

复核日期：2026-10-24。范围限于只读检查 `experiments/sp2027-r7-robustness/{adapters.py,learners.py,run.py,power.py,PROTOCOL.md,IMPLEMENTATION.md}`，并按需读取 `r7common.py`、R6 的 metric helper、冻结工件及 `verify.py` 以理解依赖。未运行新模型、采集或验证命令，未改动任何冻结实验文件；本文件是 Luna 辅助核查，不是独立人类验证。

## 结论摘要

没有在这六个目标文件中发现明确的 train/test customer 泄漏或测试标签参与拟合。实现对该性质有可读的代码路径：adapter calibration 仅接收 `captures('train')`；每个条件、目标和 prompt arm 的攻击器仅在 `rows('train')` 拟合；预测阶段检查模型包记录的训练 customer 与 test customer 不重合。`predict()` 只读取测试标签来输出评估记录。冻结记录还显式标记 `test_previously_analyzed: true`，与“post hoc 已观察 cohort”口径一致。

存在一个应修正的协议范围不一致：`PROTOCOL.md` 写功效敏感性覆盖正类客户数 5–250，但 `power.py` 和现有 `power.json` 实际覆盖 5–400，且 80% 条件的 `minimum_80pct` 明确依赖 n=400 的结果。不能把这个脚本/表称为只覆盖 5–250。只读审查没有改源文件；建议由主任务按冻结文件修改政策决定是否改协议表述。

除此以外，Tamaraw/Walkie-Talkie 等是 RPC/TLS 离线适配，不是论文原版 Tor 实现；代码和文档多处清楚限定为 adaptation。真实输入分片的抽象、模拟时钟不等于实时网络调度、CNN 的 512-cell 截断和功效近似均有披露，属于可接受的范围限制。该审查不验证“实现完全正确”，也不替代运行冻结的既有复核流程。

## 阻塞项与非阻塞限制

**需要修复的文档不一致：** PROTOCOL 的 n 范围 5–250 与代码/JSON 的 5–400 不同。当前不影响原始 R7 估计值，但影响对功效网格覆盖范围的可复现描述，建议在修改冻结文本前选择统一范围并重新核对其引用表/图。

**未发现阻塞性泄漏错误：** 本次静态审阅没有定位到测试客户参与 calibration/fitting、测试标签进入输入特征、或按 test 结果选超参的路径。这个结论限于审阅到的上述函数，不是对执行结果的独立重算。

**应保留的限制：** 真实 capture records 被转换为合成固定长度 cell 的适配；FRONT/WTF-PAD 不做真实链路竞争；Tamaraw/Walkie-Talkie 的时间是离线因果回放；CNN 仅用首尾各半、最多 512 个 cell。PROTOCOL/IMPLEMENTATION 已披露大部分限制，主文图表和文字也应保留这些限定，不能把 simulated schedule 描述为 measured latency 或原论文实现。
